# Support

## A question or a bug

Open an issue at
[github.com/vishisht16/syg/issues](https://github.com/vishisht16/syg/issues).
The form asks for what makes a report quick to act on:

- `syg version`, the operating system and architecture, and how you
  installed Syg;
- the command you ran, and what it printed;
- the smallest module that shows it, and what you expected instead.

`syg explain NAME` answers most questions about a finding, offline, and
`syg why` says where any generated field came from.

## A vulnerability

Report it privately, never in an issue: see
[reporting a vulnerability](security.md#reporting-a-vulnerability).

## An idea

Open an issue with the feature form. The [non-goals](non-goals.md) say what
Syg will not do, and why, so read them first.

## What to expect

Issues are answered as time allows, and vulnerability reports first. There is
no guaranteed response time.

The latest release is the supported one. A fix ships as a new version, so
upgrading is the fix. The [compatibility](compatibility.md) page says what a
new version may change.
